# AstraNautics Physics Engine

「物理トグルスイッチ」で切り離したブロック構造物を 6 自由度の剛体として
シミュレーションする、Valkyrien Skies / Create: Aeronautics 系の物理実装です。

現在の実装は **Phase 1（剛体コア）+ Phase 2（衝突レイヤ / 軽量化）+
Phase 3 の一部（プレイヤーの撃力で動く / 転がる、バニラ準拠の採掘）** です。

## アーキテクチャ

```
PhysicsSwitchBlock (物理トグルスイッチ / enabled ブロックステート)
   │  右クリックで ON/OFF（Shift + 右クリックは状態表示のみ）
   │  船体の隣で ON にすると、その船体をブロックに戻す（解除）
   ▼
PhysicsSwitchBlockEntity … 4 tick ごとに状態と船の有無を比較
   │   ON  → ShipAssembler.assemble()
   │   OFF → PhysicsShip.dissolve()
   ▼
ShipAssembler … スイッチを起点に 6 方向 BFS。半径/ブロック数上限つき
   │   対象: 衝突形状を持つブロックならすべて（BE 持ち・岩盤・スイッチも可）
   ▼
ShipStructure … ローカル座標のボクセルグリッド
   │   質量 = Σ ブロック質量（硬さベース: 0.4 + 0.35 × hardness、上限 6）
   │   慣性テンソル = Σ [m/6·E + m(r²E − r rᵀ)] （平行軸の定理）
   ▼
RigidBody … 位置・姿勢(クォータニオン)・線形/角速度・力/トルク
   ▼
ShipPhysics.step() … 固定ステップ (1/20 s ÷ substeps)
   1. 重力を力として加算
   2. 速度積分（減衰つき）
   3. CollisionDetector で接触生成
   4. 逐次インパルス法で接触解決（法線 + クーロン摩擦、Baumgarte 補正）
   5. 位置積分
   6. 最深貫通に対する位置補正
   ▼
PhysicsShip (Entity) … サーバーで物理を進め、位置と姿勢を同期
   ▼
PhysicsShipRenderer … クォータニオンで姿勢を適用し、全ボクセルを描画
```

## 衝突検出

- 構造物の**表面ボクセルだけ**を対象（内部は絶対に接触しない）
- 各ボクセルは OBB（辺 1 ブロック）として扱い、ワールドのブロック衝突形状
  （`VoxelShape#toAabbs`）と **SAT（分離軸定理, 15 軸）** で判定
- 得られた最小貫通軸を接触法線とし、貫通量とともに接触点を生成
- 接触は貫通量の大きい順に最大 48 点まで

## 同期

| データ | 手段 |
|---|---|
| 位置 | バニラのエンティティ位置同期（`Entity#setPos`） |
| 姿勢 | `SynchedEntityData` の FLOAT × 4（クォータニオン） |
| ボクセル構造 | `SynchedEntityData` の STRING（Base64 化したバイナリ） |
| セーブ | `PhysicsShip#addAdditionalSaveData`（構造 + 剛体状態） |

クライアントは受け取ったクォータニオンを `slerp` で補間して描画します。

## 設定 (`config/astranautics-common.toml`)

| キー | 既定値 | 説明 |
|---|---|---|
| `physics.assemblyRadius` | 10 | スイッチから構造物として切り離す半径 |
| `physics.maxBlocks` | 512 | 1 隻あたりの最大ブロック数 |
| `physics.punchSpeed` | 2.5 | 左クリックで与える撃力（目標速度 blocks/s） |
| `physics.gravity` | 32.0 | 重力 (blocks/s²) |
| `physics.substeps` | 2 | 1 tick あたりの物理サブステップ数 |
| `physics.friction` | 0.6 | 摩擦係数 |
| `physics.restitution` | 0.05 | 反発係数 |
| `physics.linearDamping` | 0.999 | 線形減衰 |
| `physics.angularDamping` | 0.995 | 角減衰 |

## Phase 2: 衝突レイヤ

| レイヤ | 実装 | 計算頻度 |
|---|---|---|
| 船 vs ワールド | 表面ボクセル OBB × ワールド `VoxelShape`（SAT） | サブステップごと |
| 船 vs 船 | バウンディングボックス → `VoxelSpatialIndex` の近傍ボクセル OBB 同士 | 1 tick に 1 回 |
| 船 vs エンティティ | エンティティ AABB × 近傍ボクセル OBB。押し出し + 上面では乗って移動 | 1 tick に 1 回 |

- 船同士は **2体ソルバ**（有効質量に両者の逆質量と角項を含める）で解き、貫通分を両者で
  半分ずつ押し離します。
- エンティティは運動学的に扱い（船を押し返さない）、上面に乗った場合は船の表面速度を
  与えて「動く足場」として機能します。
- これらのパスは `ShipPhysicsTicker`（LEVEL_TICK の END）で**レベルごとに 1 回**だけ実行します。

## アセンブリ（v3.1.0）

### 対象ブロック

`ShipAssembler` は「シミュレーションで表現できないもの」以外はすべて受け入れます。

| 区分 | 扱い |
|---|---|
| 通常ブロック（石・木材など） | 対象 |
| 岩盤・障壁・コマンドブロック・ストラクチャーブロック | 対象（クリエイティブ専用でも可） |
| BlockEntity 持ち（チェスト・かまど・看板など） | 対象（中身は保持されない） |
| 空気・流体 | 対象外 |
| 当たり判定の無いブロック（草花・たいまつ・レッドストーン） | 対象外 |
| `physics_switch` | **対象**（v3.3.0 以降）。組み立て時に一緒に切り離され、船体のブロックとして動きます |

質量はブロックごとの `destroySpeed` に基づきますが、下限を設けているため
硬さ 0 のブロック（草ブロック等）でも質量 0 にはなりません。

### 状態機械

```
        switch / 右クリック
   OFF ───────────────────────▶ ON
    ▲                            │
    │  dissolve 成功             │ assemble 成功 → ship 生成
    └────────────────────────────┘
                                 │ assemble 失敗
                                 ▼
                       ON のまま + 理由をログ/チャット
                       60 tick 後に再試行（点滅しない）
```

* アセンブルは**スイッチを押した瞬間**に同期実行され、結果がチャットに出ます。
* tick 側（4 tick ごと）は「ON なのに船が無い」「OFF なのに船がある」を
  突き合わせて収束させるフォールバックです。
* 組み立て後はスイッチも船体の一部になるため、解除は**船体を素手で右クリック**（＝スイッチ OFF）。
  戻すときスイッチのブロックステートは `enabled=false` に戻します（再組み立て可能）。
* v3.2.0 で `physics_assembler` を削除。既存ワールドのアセンブラは
  `RegistryEvent.MissingMappings` でスイッチに remap されます（NBT 互換）。
* `shipId` / `LastBlocks` / `LastReason` はブロックエンティティ NBT に保存されます。

### クライアント同期

* 位置: バニラのエンティティ同期
* 姿勢: `SynchedEntityData` の FLOAT × 4（クォータニオン）
* 構造: `SynchedEntityData` の文字列（Base64、1 ボクセル 10 バイト）+
  スポーン時は `IEntityAdditionalSpawnData` でも送信。これにより、
  組み立て後に近づいてきたプレイヤーにも船が表示されます。
* 当たり判定: 構造のワールド AABB（回転後の半サイズ）を `makeBoundingBox` で返すため、
  カリング・船 vs エンティティ・船 vs 船のブロードフェーズが実寸で動きます。

### 例外安全（v3.1.1）

物理演算・組み立て・復元はどれもワールドを壊し得る処理なので、境界ごとに例外を捕捉します。

* `ShipAssembler.assemble` — 走査・構造生成・エンティティ生成それぞれを捕捉し、
  `Result(Reason.EXCEPTION, detail)` として返す（ブロックは消さない）。
* `PhysicsAssemblerBlockEntity.serverTick` — 失敗したらログを出して再試行を 240 tick 後ろに倒す。
* `PhysicsShip.tickServer` — 物理計算で例外が出たら**その船だけ**ブロックに戻して除去。
  サーバースレッドは落とさない。
* `PhysicsShip` の当たり判定ベクトルは遅延生成（`Entity` のコンストラクタが
  `setPos -> makeBoundingBox` を呼ぶため、フィールド初期化子より先に走る）。

## Phase 3: プレイヤーの撃力（v3.2.0）

構造物を**叩く（左クリック）**と剛体に撃力がかかります。

```
見た目: 攻撃者の目 → 最も近い表面ボクセル中心を接触点 p とする
撃力:   J = punchSpeed × m / (48 + m) × m方向ベクトル
        （軽い構造物ほど目標速度に近づき、重い構造物はほとんど動かない）
適用:   RigidBody.applyImpulseAt(J, p)
        Δv = J / m                   … 並進
        Δω = I⁻¹ (p − com) × J       … 回転（端を叩くと転がる）
```

* `Entity#isPickable` / `isAttackable` を有効化し、`hurt()` を上書きしています
  （体力は持たず、ダメージでは壊れません）。
* 叩いた瞬間に `wake()` してスリープを解除、接触キャッシュを捨てます。
* 効果音は叩いたブロックの `SoundType#getHitSound`。
* 角度・位置のインパルスはどちらも既存のソルバにそのまま乗るので、
  転がり・跳ね返り・積み木の崩れはすべて通常の衝突解決で表現されます。
* `LevelCollisionSource` は `physics_switch` を衝突形状なしとして扱います
  （制御ブロックが船体に埋め込まれていても船が固定されないように）。

### Phase 3 の残り

* 空気力学（揚力・抗力・プロペラ推力）
* 船上でのブロック操作 / インベントリ / レッドストーン連携
* 船単位の並列化（現在はサーバースレッドで直列）

## 増築（v3.3.0）

組み立てた後にブロックを足せます。

```
1. プレイヤーの視線を船体の表面ボクセルに当てる
   （ワールド→局所変換: p_local = R⁻¹ (p_world − com_world) + com_local）
2. 各ボクセルの AABB [x, x+1]³ と視線レイのスラブ判定で最寄りのヒットを取る
3. ヒットした面の外側セル（法線方向 +1）を空きセルとして採用
4. ShipStructure.of(全ボクセル) で質量・慣性・表面集合を作り直す
5. 重心が動いたぶんだけ剛体位置を R(com_new − com_old) だけ平行移動し、
   線形速度を m_old/m_new でスケール（運動量の目安）して見た目を保つ
```

* 追加は `AstraConfig.MAX_BLOCKS` まで。クリエイティブ以外ではアイテムを 1 個消費します。
* 追加後は構造をクライアントへ再同期（`structureSyncPending`）。

## 取り外し / 採掘（v3.5.0）

* **左クリック長押し** → 視線の先のボクセルを、**バニラと同じ計算式**で壊します
  （`state.getDestroyProgress(player, level, pos)` を 1 tick ぶんずつ積算。硬さ・適正ツール・
  効率・水中ペナルティまでバニラ準拠）。たとえば硬さ 1.5 の石は素手で 7.5 秒、
  木のツルハシで約 1.1 秒です（バニラと同じ）。
* バニラはエンティティへの攻撃パケットをクリックごとに 1 回しか送らないため、
  **クライアントが `MineTick`（`astranautics:physics`, `shipId` + `cell`）を 2 tick ごとに送信**し、
  サーバーが `VoxelMining` で進捗をプレイヤー（UUID）× ボクセルごとに保持します。
  パケットが 10 tick 途切れると進捗は破棄されます（バニラの「離すとリセット」相当）。
* **クリエイティブは 1 tick で破壊**（`abilities.instabuild`）。
* 壊したブロックはドロップし、チェストなどは保存されている中身もドロップします。
* 破壊中は 5 tick ごとにヒット音（`SoundType.getHitSound`）を鳴らします。
* **短い左クリックは「叩いて動かす」**（`applyImpulseAt`）。押し続けて採掘に移行した場合は
  `PhysicsShip#undoLastPunch` が直前 6 tick 以内の撃力を打ち消すので、船体が逃げません。
* 最後の 1 ブロックを外すとエンティティは消滅（構造が空になるため）。
* 追加と削除は同じ `applyVoxels` を通り、重心移動の補正・速度スケール・
  質量/慣性の再計算・クライアント再同期を共通処理しています。

## 物理化の解除（v3.5.0）

* **船体の隣に物理トグルスイッチを置き、右クリックで ON** → そのスイッチは
  `PhysicsSwitchBlockEntity#apply` の中で `findNearbyShip`（バウンディングボックスから
  8 ブロック以内で最も近い船体）を見つけ、`PhysicsShip#dissolve` でその場にブロックを戻します。
* 溶解後スイッチは自動で **OFF** に戻ります（次に組み立てたいときに再度 ON にできます）。
* 船体を素手で右クリックしても解除されません（状態表示のみ）。
* スイッチのブロックエンティティが船を覚えている場合（ON のまま船が残っている等）は
  従来どおり OFF で `dissolveNow` も動きます。

## ブロックエンティティ（チェスト等）

* 組み立て時に各ブロックの `BlockEntity#saveWithoutMetadata()` を取得し、
  ローカル座標 → NBT のマップとして **エンティティ NBT に保存**（`BlockEntities`）。
* 解除時はブロックを戻した直後に `BlockEntity#load()` で中身を復元。
* 船上のチェスト / 樽 / シュルカーボックスを右クリックすると、
  保存 NBT を `Container` でラップして `ChestMenu.threeRows` を開きます（書き込みは `setChanged` 経由）。
* スイッチのブロックエンティティだけは引き継ぎません（復元時に OFF で作り直すため）。

## 当たり判定（エンティティ）

`EntityShipCollision` が 1 tick に 1 回、船ごとに周囲のエンティティを処理します。
v3.5.1 で「最深の接触を 1 つ選んで押し出す」方式をやめ、**接触の向きごとに分けて解決**する
ようにしました（これが「上を歩くと遅い」「触れているとガクガクする」の修正本体です）。

* 表面ボクセル OBB × エンティティ AABB（`Obb.intersect`）で、上向き / 下向き / 横向きの
  接触をそれぞれ**別々に**集計する
* **支持（法線が上、y > 0.5）** — 貫通深さぶん上へ分離（`pen + 0.001`、最大 0.5）。
  判定は**足元を 0.06 ブロック下へ伸ばした箱**（`SUPPORT_PROBE`）で行います。接触は
  「重なり > 0」で検出するため、ちょうど乗っている（重なり 0）状態では毎 tick 検出できず、
  重力キャンセルが 1 tick おきに ON/OFF して**10 Hz で視点が上下**していました（v3.5.5 で修正）。
  傾いた船体でも正しいのは「貫通深さで押し出す」方で、v3.4.0 の
  「ボクセル中心 + 0.5 へスナップ」は傾き・段差で座標が飛ぶため廃止しました。
  下向き速度だけ 0 にし、**プレイヤーの水平速度には一切触らない**（＝歩く速さが落ちない）。
  デッキの表面速度 × 1 tick を位置に足して、動く甲板に一緒に運ばれる
* **天井（法線が下）** — 壁と**同じ計算方法**で扱います。判定は**頭を 0.12 ブロック切り落とした箱**
  （`HEAD_CLEARANCE`）で行い、身体に本当に掛かっているときだけ `pen + 0.004` だけ下へ分離し、
  上向き速度を 0 に。支持（甲板）と同時に掛かった場合は**支持を優先**して天井側は無視します
  （船内の低い場所で上下に押し合う＝振動になるため）
* **壁（水平法線）** — 横へ押し出し、壁へ向かう速度成分だけを除去（最大 0.3 ブロック/パス）。
  ただし判定は**足元を 0.12 ブロック切り落とした箱**で行います。立っているあいだ足が
  1 tick ぶん沈むと、隣の甲板ブロックと浅く重なって SAT が水平軸を選び、
  「押し返されて速度が消える」＝**歩くと進んだり止まったりする**原因になるためです
* 1 tick あたり最大 3 パス。0.02 ブロック未満の接触は無視（マイクロ接触によるガタつき防止）
* **サーバーとクライアントの両方**で同じ解決を実行します。どちらも**エンティティの
  tick が全部終わった後**です（サーバー: `ShipPhysicsTicker` の `LevelTickEvent.END`、
  クライアント: `ClientShipCollision` の `ClientTickEvent.END`）。
  v3.5.1 まではクライアント側を「船エンティティの tick の中」で実行していたため、
  エンティティ ID の順番で船がプレイヤーより先に tick すると、補正 → プレイヤー自身の
  重力で 0.08 沈む、を毎 tick 繰り返して**見た目が揺れて**いました（今回の修正の本体）。
  クライアント側で補正するのは**ローカルプレイヤーだけ**です（他はサーバーの位置が正）
* 補正が 0.4 ブロック未満なら**パケットを送らず** `ServerPlayer#setPos` で揃えるだけ。
  速度変化も 0.1 未満なら `hurtMarked` を立てません（両側が同じ計算をするので、
  毎 tick のモーションパケットはプレイヤーの入力を上書きするだけ）。
  毎 tick `connection.teleport` + `hurtMarked` を送っていた v3.4.0 までは、サーバーの補正と
  クライアントの自前シミュレーションが喧嘩して、立っているだけで揺れていました
* 船はこの処理では起こしません（寝ている船は完全に静止するので、その上は一番安定します）

### 甲板の上で足元を固定する（v3.5.6）

`ShipPlatformSupport` が `PlayerTickEvent.START` で、前 tick に甲板へ立っていたプレイヤーの
**足元 Y を、衝突解決が決めた高さにピン留め**します（`EntityShipCollision#supportHeight`）。

* プレイヤー自身の tick では重力で 0.078 沈みますが、tick 末の衝突解決が同じだけ押し戻すので、
  tick の開始位置（`yo`）と終了位置（`y`）が一致し、**描画補間の移動量が 0** になります
  （＝カメラが動かない＝世界が揺れない）
* v3.5.3〜v3.5.5 は「重力を打ち消す」方式でしたが、重力の丸め誤差ぶんの残留沈み込みがあり、
  毎 tick 数ミリの補正が入っていました。v3.5.5 で接地検出をプローブ箱にしたことで補正が
  毎 tick 安定して走るようになり、その残留が「世界全体が揺れる」として見えていました
* 上昇中（`vy > 0.02`）はピン留めしません。ジャンプは `aiStep` で `0.42` に上書きされます
* 支持の記録は `WeakHashMap` に「時刻 + 高さ」で保持し、2 tick で失効、0.08 以上ずれたら無効
* クライアント側は `ShipWorld` の船リスト（次元ごと）を使うので、レベル全体のエンティティ走査は
  しません（クライアントの負荷対策）

### 静止した船を本当に静止させる（v3.5.7）

甲板の高さは船体の姿勢から求めるので、**船体が数ミリ動けば甲板も数ミリ動きます**。v3.5.6 で
プレイヤー自身はピン留めできましたが、船体側が起きたまま微小に動いていると、その動きが
そのままカメラに乗ります（＝まだ世界が揺れる）。

* 原因は接触ソルバの残留速度です。重力と法線インパルスは 1 tick で完全には釣り合わず、
  「静止しているはずの船」に毎 tick 数 mm/s が残ります。睡眠判定のしきい値（0.05）を
  超えていると `sleepTicks` が積み上がらず、**永久に起きたまま**になります
* `ShipPhysics#settleRestingBody` を追加。**接触法線がすべて上向き（＝上に乗っている）** ときだけ、
  鉛直速度が 0.05 未満なら 0.2 倍、全体がほぼ静止（< 0.06 m/s、< 0.1 rad/s）なら 0.35 倍に
  減衰させます。端から傾き落ちる箱は横向きの接触を持つので対象外（動きを殺しません）
* これで残留速度が消え、`sleepTicks` が積み上がって**船が睡眠状態に入る＝座標が完全に固定**。
  睡眠中は衝突解決もプレイヤーも何も動かしません
* `/astranautics watch` を追加。60 tick のあいだ「プレイヤーの Y」と「乗っている船の Y」を
  記録し、変化幅と 1 tick の最大変化、船の速度・角速度・睡眠状態をチャットに出します。
  **どちらが動いているか**が一目で分かります（赤＝動いている側）

### 継ぎ目から落ちない支持判定（v3.5.8）

「ブロックとブロックの間から落ちる」の原因は、支持判定を **SAT（分離軸）** で行っていたことでした。
SAT は「いちばん浅い軸で押し出す」ので、**2 つの甲板ブロックの継ぎ目の上**や**甲板の端**では、
横方向の重なりが毎 tick の沈み込み（約 0.08）より小さくなります。すると接触が「壁」と分類され、
壁判定は足元を 0.12 切り落とした箱で再判定するため**その接触は捨てられ**、支持が消えて落下します。

`FootprintSupport` は問いを変えます。**「足元の真下にある上面はどれで、高さはいくつか」**だけを
見ます。隣り合うボクセルの上面は隙間なくタイルするので、継ぎ目に穴はできません。

* ワールドの点 (x, z) をボクセルローカルへ逆変換し（`lx, lz` の 2×2 連立方程式）、
  `|lx|, |lz| <= 0.5` なら上面の高さ `center.y + m01*lx + m11*0.5 + m21*lz` を返します
* 足元の**5 点**（四隅 + 中心、0.05 内側）で調べ、いちばん高い上面を採用
* 上面が足元より最大 1.0 ブロック下まで（`MAX_SUPPORT_DEPTH`）と、0.06 上までを支持とします。
  落下は 1 tick 最大 0.2 ブロックなので**落下中に飛び越えることはありません**
* 傾いた船でも上面の高さがそのまま出るので、押し上げ量は**鉛直距離**（法線で割らない）
* SAT の支持判定は残してあります（船が横から突っ込んでくるような深いめり込み用）。両方の
  大きいほうを採用します

### 軽量化（v3.5.8）

| 箇所 | まで | 現在 |
| --- | --- | --- |
| ボクセル索引の再構築 | 毎 tick・船ごと（表面ボクセル数ぶんのオブジェクト生成） | **姿勢が変わったときだけ**（`indexStale` + 姿勢比較） |
| 構造データの同期 | 変更後 20 tick 連続で全ブロックをエンコードして送信 | **1 回だけエンコード**し 3 tick 再送（新規トラッカーには通常の同期で届く） |
| クライアントの衝突 | 次元内の全船についてエンティティ検索 | **プレイヤーの箱と交差する船だけ** |
| 立っているだけの解決 | 毎 tick 全ボクセルを SAT | **姿勢が固まった船＋水平移動なしなら記録高さを復元**（O(1)） |

## 物理化解除（v3.5.9）

**物理化した船体にスイッチを置くと、それはワールドのブロックではなく「船体のボクセル」になります**
（船体への右クリックは増築として扱われるため）。そのため `PhysicsSwitchBlock#use` は呼ばれず、
右クリックしても解除できませんでした。

v3.5.9 から `PhysicsShip#interact` が**視線の先のボクセルがスイッチか**を最初に判定し、
スイッチならその場で解除（ブロックを元の位置へ戻す）します。

* 視線は `raycastHull`（船の姿勢の逆回転でローカル座標へ変換）で当てた**実際のボクセル**
* スニーク + 右クリックは状態表示のみ（誤爆で解除しない）
* 解除時に戻るスイッチは **OFF**（`dissolve` が `ENABLED=false` で置き直す）なので、
  そのスイッチを次に押せば再び物理化できます
* 船の**隣**にスイッチを置いて押す従来の方法もそのまま動きます

### 置き直したスイッチは ON 表示（v3.5.10）

スイッチを壊しても物理化は保たれます（船体は独立した剛体のため）。そのため、**置き直した
スイッチは「物理演算が ON の状態」を表示するのが正しい**はずですが、以前は既定値の OFF
テクスチャで置かれ、押すと「もう一度アセンブル」しようとしていました。

* **船体に載せる**（右クリックで増築）: `PhysicsShip#attachBlock` が
  `PhysicsSwitchBlock.ENABLED = true` にします。ON モデルで描画され、右クリックで解除できます
* **船体の隣に置く**: `PhysicsSwitchBlock#onPlace` が 2.0 ブロック以内の船体を見つけると
  `PhysicsSwitchBlockEntity#linkShip` で**その船体にリンク**し、状態を ON にします。
  以後は「その船体の操作スイッチ」として働きます（押すと解除）
* リンクされたスイッチは `linked` フラグを持ち、**船体が消えたら自動で OFF に戻ります**
  （そうしないと、解除した直後に置かれたブロックを勝手に再アセンブルしてしまいます）
* 同じブロックの状態変更（OFF に戻す操作など）は `onPlace` では「設置」と区別して無視するため、
  リンクしたスイッチでも普通にオフにできます

## 空気力学（v3.6.0）

浮力・推力・空気抵抗・水の浮力を実装しました。すべて **1 tick ぶんの「力積」** として、
力が働く点に加えます。force アキュムレータではなく力積にしているのは 2 つ理由があります。

* ソルバは substep するので、毎 tick の `applyForce` は**最初の substep でしか効かない**
* 力積を**作用点**に加えるとトルクが出る。片側に寄せた気球は船を傾け、偏心したプロペラは
  船を回す — これが「エレベーター」ではなく「乗り物」になる所以です

### 気球（`astranautics:balloon`）

* 1 個あたり `aerodynamics.balloonLift`（既定 1.5）の質量を支えます。気球自身の質量は約 0.5
  なので、木 1 個あたり気球 1.5 個で釣り合います
* 力積は気球群の**重心**に加えるので、片側に固めると傾きます
* 気球の浮力が自重を超えている船は、接地して眠っていても**自動で起こします**
  （`Aerodynamics#liftsItself`）。それ以外の船は従来どおり睡眠して完全停止します

### プロペラ（`astranautics:propeller`）

* 動力付きの 1 個あたり `aerodynamics.propellerThrust`（既定 80）を `FACING` 方向へ
* `FACING` は**設置したときプレイヤーが向いている水平方向**（船体に増築するときも同じ）
* 船体のボクセルはブロックではないので `use()` は来ません。`PhysicsShip#interact` が
  視線先のボクセルを判定して `POWERED` を反転します（スイッチ解除と同じ仕組み）。
  状態が変わると構造を作り直し（`applyVoxels`）、キャッシュされた推力源リストが更新されます

### 空気抵抗

`F = -k * A * |v| * v`（`k = aerodynamics.airDrag`）。断面積 `A` は船のローカル AABB を
速度方向へ射影して求めます。速度に対する**減衰率**として適用するので substep 数に依存しません。
1 tick で止まりきらないよう上限 0.8 を掛けています。角速度にも半分だけ効かせています。

### 水の浮力（アルキメデス）

* **排水体積** = 水に入っているボクセル数 + **船体が密閉している空気の体積 × 浸水率**
* 密閉空気は組み立て時に**外側からの flood fill** で数えます（`HullVolume`）。
  外から到達できない空気セルが「密閉」です。中空の木の船は浮き、同じ木を solid に積むと沈みます
* 浮力 = 排水体積 × `aerodynamics.waterDensity` × 重力。作用点は水に入っているボクセルの重心
* 水中では追加の線形減衰（`aerodynamics.waterDrag`）がかかり、船はすぐ止まります
* 毎 tick 全表面ボクセルの `getFluidState` を引くのは無駄なので、まず船の中心と最下部の
  4 点で水を探し、無ければ「乾いている」と判定します

### Create: Aeronautics に合わせた調整（v3.6.1）

参照実装（Create: Aeronautics / Simulated-Project）の式を確認し、次の 4 点を合わせました。

**1. 気圧は高度で下がる** — `p(y) = e^(-0.004 (y - 63))`（`ServerBalloon` / `AeroPhysics`）

* 浮力・推力・抵抗の**すべて**に掛かります
* 船は `浮力 × p(y) = 重量` になる高度まで上がって**そこで釣り合います**（高さ制限ではなく自然な天井）
* y=256 で p≈0.46（浮力が半分）、y=1000 で p≈0.024
* `aerodynamics.pressureFalloff` を 0 にすると高度効果なし

**2. プロペラは流速で頭打ち** — `thrust = 推力 × p(y) × max(0, 1 - V/airflow)`
（`BlockEntityPropeller#getAirflowScaling`）

* `V` は**推力方向への船の速度**。`airflow`（既定 24 ブロック/秒）に達すると推力が 0
* **どんなにプロペラを増やしても最高速度は airflow を超えません**（Aeronautics と同じ性質）

**3. 気球は抵抗そのもの** — 1 個あたり `0.33 × p(y)` の線形抵抗（`floating_materials`）

* 大きな気球船が遅いのはこれが理由です。船体断面積の二次抵抗に上乗せされます

**4. プロペラはトルクを出さない**（既定）— Aeronautics は「プロペラはトルクを生まない」と
明示的に例外にしています（`0.2 × sails^1.5 × RPM` の推力のみ）。そうしないと航空機が自分の
エンジンでロール／ヨーして操作できません。`aerodynamics.propellerTorque = true` にすると
従来どおり偏心推力で船が回ります（船外機っぽい挙動）。

### 設定（`config/astranautics-common.toml`）

```toml
[aerodynamics]
enabled = true
balloonLift = 1.5        # 気球 1 個が支える質量（海面高度で）
propellerThrust = 80.0   # プロペラ 1 個の推力
propellerAirflow = 24.0  # この速度で推力 0（＝最高速度）
propellerTorque = false  # true で偏心推力を有効に
airDrag = 0.01           # 船体断面積の二次抵抗
balloonDrag = 0.33       # 気球 1 個あたりの線形抵抗
pressureFalloff = 0.004  # 気圧の高度減衰（0 で無効）
waterDensity = 1.0
waterDrag = 3.0
```

## 駆動系（v3.7.0）

### ネットワーク (`RotationalNetwork`)

船体を組み直すたび（`ShipStructure.of`）に、回転ブロックだけを BFS でまとめます。

| 種類 | 軸 | 備考 |
| --- | --- | --- |
| `SteamEngineBlock` | `AXIS` | 動力源 |
| `ShaftBlock` / `FlywheelBlock` | `AXIS` | 伝達（はずみ車は慣性） |
| `CogwheelBlock` | `AXIS` | **何とでも噛み合う継手** |
| `PropellerBlock` | `FACING` の軸 | 消費者（シャフトは背面から） |

噛み合い判定は 2 行:

```java
if (a.kind() == GEAR || b.kind() == GEAR) return true;   // 歯車は角を曲げる
return a.axis() == faceAxis && b.axis() == faceAxis;     // それ以外は軸方向に並ぶ
```

結果は `ShipStructure#thrusters()` の各 `ThrustSource` に「駆動元のエンジンセル一覧」として
焼き込まれるので、**tick 中の回転ネットワーク探索はありません**。

### エンジンの状態

船体のブロックはもうワールドに無いので、エンジンは block entity になれません。

* ランタイム: `PhysicsShip` の `Map<BlockPos, EngineState>`（`throttle` / `burn` / `rpm`）
* 保存: `addAdditionalSaveData` の前に `blockEntities` NBT（`Throttle` / `Burn` / `Rpm`）へ鏡映
* 組み直し時: `syncEngines()` がセル単位で引き継ぎ（増築しても回転数がリセットされない）
* 焚き口の `lit` ブロック状態はスロットル操作・燃料補給・燃料切れでだけ切り替えます
  （毎 tick 組み直さないため）

### 回転数と推力

```java
target = burning ? throttle * rpmPerThrottle : 0
rpm   += (target - rpm) * min(1, dt / (response + flywheelResponse * flywheels))
burn  -= (1 + throttle)          // スロットルを開くほど速く減る
```

プロペラ推力の倍率（`Aerodynamics.thrustPower`）:

```java
1 + thrustBoost * min(1, maxEngineRpm / (rpmPerThrottle * 4))
```

* 繋がっていないプロペラは倍率 1（従来どおりの基本推力）
* エンジンが止まっていても倍率 1（`POWERED` の右クリック ON はそのまま効く）
* `engines.enabled = false` で倍率は常に 1

### 睡眠との関係

回転中のエンジンがある船は**眠りません**（`updateSleepState` が早期 return）。睡眠中に
エンジンが回り出した場合も `tickEngines` → `wake()` で起こします。

### 立ち位置のがくつき（v3.9.0）

支持高さは毎 tick 足元のボクセルから測り直すので、船がわずかに動いていると **数 mm の差**が
毎 tick 交互に出ます。それをそのまま `setPos` すると、カメラはその差を毎 tick 描くので画面が揺れます。

```
if (previous != null && sameShip && |previous.y - y| <= 0.02) {
    // サンプリング誤差: 前の高さを維持し、実際にもその高さへ戻す
}
```

* 2 cm 以内の差は**無視**（`SUPPORT_HYSTERESIS = 0.02`）。位置が変わらないので描画も動かない
* それ以上の差（エレベーター・段差・接地のやり直し）は今までどおり追従
* `ShipPlatformSupport` も、すでに同じ高さなら `setPos` を呼ばない

`/astranautics watch` の「プレイヤーY 変化幅」がこの値です。0 に近ければ揺れていません。

## 回転ブロック（v3.10.0）

### 角度の持ち方

`RotatorBlock` は `angle`（0–23、×15°）と `powered` を**ブロック状態**に持ちます。船体の構造は
クライアントへ同期されるので、**ダイヤルは現在値をそのまま読めます**（開くときの通信ゼロ）。
変更時だけ `SetRotator` パケットをサーバーへ送り、サーバーが `ShipStructure` を組み直します。

### 回転

`Rotators`（純粋な数式、ユニットテストあり）:

* 方位 = `atan2(-fwd.x, -fwd.z)`（`fwd = R·(0,0,-1)`）
* 傾き = `atan2(up.z, up.y)`（`up = R·(0,1,0)`）
* 差分は**最短経路**（`shortestDelta`、`(-180, 180]`）
* 1 tick の回転量 = `speed / 20`。目標に届く場合は**差分ちょうど**を回すので、行き過ぎも残差も出ない
* 適用は `orientation = rotation_world * orientation`（JOML は `premultiply` を持たないのでこの順序で組む）

```java
Rotators.stepTowards(body.orientation, mode, target, step);
body.angularVelocity.zero();      // 姿勢を直接動かすので角速度とは喧嘩させない
body.updateRotationMatrix();
indexStale = true; wake(); pushOrientation(); updateBoundingExtents();
```

### レッドストーンの読み方

船体のブロックはワールドに存在しないため、`level.getBestNeighborSignal` を
**そのブロックが居る位置**（hull 変換で求めたワールド座標）と、その**6 近傍**で評価します。
つまり**船体の外壁に接したレバー／線**がそのまま信号源になります。

## 互換性（v3.5.9）

* **非フルブロック**: `VoxelShapes` が `BlockState#getCollisionShape` から各ボクセルの
  ローカル当たり判定を取得します（スラブ・階段・フェンス・壁・MOD のブロック形状）。
  `ShipStructure` が保持し、`VoxelSpatialIndex.Entry` が**半サイズ**を持つので、
  エンティティの当たり判定（`EntityShipCollision` の OBB、`FootprintSupport` の上面高さ）と
  船-vs-ワールドの接触（`CollisionDetector`）の両方が実際の形状を使います
* **当たり判定の無いブロック**（松明・花・看板など）は船体に載ったまま**衝突しません**
  （衝突インデックスから外すだけなので描画はそのまま）
* **他 MOD のコンテナ**: 保存 NBT が `Items` リストを持つブロックなら、バニラのチェスト画面で
  中身を開けます。スロット数は保存データの最大スロットから決めるので、
  27 スロットを超えるコンテナでも**中身が消えません**（画面に出るのは 3 行分）
* **他 MOD のツール**: 船体への右クリックで「何もしない」場合は `InteractionResult.PASS` を
  返すようにし、スニーク + アイテム所持も同様に他へ渡します。船体がクリックを飲み込まなくなりました

船が睡眠状態（またはクライアントで姿勢が変化していない）で、プレイヤーが同じ位置に立っている
場合、1 tick の沈み込みは必ず「記録した高さへ戻す」だけなので、ボクセルを 1 つも見ません。

## ブロックエンティティ（チェスト等）

* 組み立て時に各ブロックの `BlockEntity#saveWithoutMetadata()` を取得し、
  ローカル座標 → NBT のマップとして **エンティティ NBT に保存**（`BlockEntities`）。
* 解除時はブロックを戻した直後に `BlockEntity#load()` で中身を復元。
* 船上のチェスト / 樽 / シュルカーボックスを右クリックすると、
  保存 NBT を `Container` でラップして `ChestMenu.threeRows` を開きます（書き込みは `setChanged` 経由）。
* スイッチのブロックエンティティだけは引き継ぎません（復元時に OFF で作り直すため）。

## 当たり判定（エンティティ）

`EntityShipCollision` が 1 tick に 1 回、船ごとに周囲のエンティティを処理します。
v3.5.1 で「最深の接触を 1 つ選んで押し出す」方式をやめ、**接触の向きごとに分けて解決**する
ようにしました（これが「上を歩くと遅い」「触れているとガクガクする」の修正本体です）。

* 表面ボクセル OBB × エンティティ AABB（`Obb.intersect`）で、上向き / 下向き / 横向きの
  接触をそれぞれ**別々に**集計する
* **支持（法線が上、y > 0.5）** — 貫通深さぶん上へ分離（`pen + 0.001`、最大 0.5）。
  判定は**足元を 0.06 ブロック下へ伸ばした箱**（`SUPPORT_PROBE`）で行います。接触は
  「重なり > 0」で検出するため、ちょうど乗っている（重なり 0）状態では毎 tick 検出できず、
  重力キャンセルが 1 tick おきに ON/OFF して**10 Hz で視点が上下**していました（v3.5.5 で修正）。
  傾いた船体でも正しいのは「貫通深さで押し出す」方で、v3.4.0 の
  「ボクセル中心 + 0.5 へスナップ」は傾き・段差で座標が飛ぶため廃止しました。
  下向き速度だけ 0 にし、**プレイヤーの水平速度には一切触らない**（＝歩く速さが落ちない）。
  デッキの表面速度 × 1 tick を位置に足して、動く甲板に一緒に運ばれる
* **天井（法線が下）** — 壁と**同じ計算方法**で扱います。判定は**頭を 0.12 ブロック切り落とした箱**
  （`HEAD_CLEARANCE`）で行い、身体に本当に掛かっているときだけ `pen + 0.004` だけ下へ分離し、
  上向き速度を 0 に。支持（甲板）と同時に掛かった場合は**支持を優先**して天井側は無視します
  （船内の低い場所で上下に押し合う＝振動になるため）
* **壁（水平法線）** — 横へ押し出し、壁へ向かう速度成分だけを除去（最大 0.3 ブロック/パス）。
  ただし判定は**足元を 0.12 ブロック切り落とした箱**で行います。立っているあいだ足が
  1 tick ぶん沈むと、隣の甲板ブロックと浅く重なって SAT が水平軸を選び、
  「押し返されて速度が消える」＝**歩くと進んだり止まったりする**原因になるためです
* 1 tick あたり最大 3 パス。0.02 ブロック未満の接触は無視（マイクロ接触によるガタつき防止）
* **サーバーとクライアントの両方**で同じ解決を実行します。どちらも**エンティティの
  tick が全部終わった後**です（サーバー: `ShipPhysicsTicker` の `LevelTickEvent.END`、
  クライアント: `ClientShipCollision` の `ClientTickEvent.END`）。
  v3.5.1 まではクライアント側を「船エンティティの tick の中」で実行していたため、
  エンティティ ID の順番で船がプレイヤーより先に tick すると、補正 → プレイヤー自身の
  重力で 0.08 沈む、を毎 tick 繰り返して**見た目が揺れて**いました（今回の修正の本体）。
  クライアント側で補正するのは**ローカルプレイヤーだけ**です（他はサーバーの位置が正）
* 補正が 0.4 ブロック未満なら**パケットを送らず** `ServerPlayer#setPos` で揃えるだけ。
  速度変化も 0.1 未満なら `hurtMarked` を立てません（両側が同じ計算をするので、
  毎 tick のモーションパケットはプレイヤーの入力を上書きするだけ）。
  毎 tick `connection.teleport` + `hurtMarked` を送っていた v3.4.0 までは、サーバーの補正と
  クライアントの自前シミュレーションが喧嘩して、立っているだけで揺れていました
* 船はこの処理では起こしません（寝ている船は完全に静止するので、その上は一番安定します）

### 甲板の上で重力を打ち消す（v3.5.3）

`ShipPlatformSupport` が `PlayerTickEvent.START` で、前 tick に甲板へ立っていたプレイヤーの
**縦速度をちょうど 1 tick ぶんの重力（0.08）に置き換えます**。バニラは
`(v.y - 0.08) * 0.98` を適用するので、この tick の正味の上下移動は 0 になります。

* 沈み込みが起きない → 毎 tick の位置補正も、足元と隣ブロックの浅い接触も発生しない
* ジャンプ入力はこの後（`aiStep`）で `0.42` に上書きされるので、ジャンプは普通にできる
* 甲板から離れれば支持が切れ、そのまま通常の落下に戻る（`EntityShipCollision` が
  `WeakHashMap` で「前 tick に支持されていたか」を保持、2 tick で失効）
* `Slow Falling` があるときは 0.01 を使う（バニラの重力と同じ値）
* 支持は上向き速度のとき（上昇中）は記録しません（ジャンプ中の誤判定防止）
* 支持は「甲板に触れているか」だけでなく**そのときの高さ**も記録し、次 tick に
  `0.08` 以上ずれていたら支持を無効にします（段差を下りる / 船が離れて落ちる場合に、
  重力キャンセルが 1 tick だけ効いて浮く＝ガクつきを防ぐ）
* 分離量が 0（＝ちょうど乗っている）でも支持は**毎 tick 記録**します。ここが抜けると
  重力キャンセルが 1 tick おきに ON/OFF して 10 Hz の上下動になります

## 診断

* `/astranautics diag` — 周囲 32 ブロックのスイッチ状態、船の質量・ブロック数・
  スリープ状態、ON なのに船が無い場合の「組み立てた場合のブロック数」を表示。
* スイッチを Shift + 右クリック — ON/OFF、船 UUID、対象ブロック数、直近の結果（組み立て前）。
* 船体を素手で右クリック — ブロック数・質量・速度（組み立て後）。
* 物理化解除は船体の隣にスイッチを置いて ON（スイッチは自動で OFF に戻ります）。

## 軽量化

| 手法 | 効果 |
|---|---|
| **ウォームスタート**（`ContactCache`） | 前ステップのインパルスを初期値に使う。反復回数 8 → **4** でも同等の安定性 |
| **接触点キーの量子化** | 位置を 1/4 ブロックに量子化してフレーム間で接触を対応付け |
| **スリープ** | 静止した船（既定 40 tick 連続で低速）は物理計算を完全にスキップ。近接する船・エンティティ・スイッチ操作で起床 |
| **`VoxelSpatialIndex`** | 表面ボクセルを 2 ブロック格子に索引化。船同士・エンティティ・描画の広域判定が O(n²) にならない |
| **`CachingCollisionSource`** | 1 ステップ内のワールドブロック問い合わせをメモ化（同じセルを何十個ものボクセルが参照する） |
| **表面ボクセルのみ** | 衝突判定・描画とも内部ボクセルを除外。中実な構造物でもコストは表面積に比例 |
| **可変サブステップ** | 速度が上がったときだけサブステップを増やす（最大 16） |
| **パラメータのスナップショット** | `PhysicsParams` を tick 開始時に 1 回だけ構築（毎ステップのコンフィグ参照を回避） |

## 既知の制限（Phase 3 以降）

1. **翼（迎え角による揚力）なし** — 気球の浮力とプロペラ推力は実装済み（v3.6.x / v3.7.0）
2. **スレッディングなし** — 物理はサーバースレッドで計算（船ごとの並列化は未着手）
3. 描画はボクセル単位の `renderSingleBlock`。表面のみに絞ったが、巨大な船では依然重い
4. クライアント補間は姿勢のみ（位置はバニラの補間に依存）
5. 船の上でのブロック設置・破壊、レッドストーン、インベントリ等は未対応
6. エンティティは運動学的（プレイヤーが船を押せない）
7. 船 vs ワールドの接触は離散判定（高速時はサブステップ増加で緩和）

### Phase 3 候補

- 翼・エアロン・エレベーター（迎え角による揚力と操縦）
- 回転数の見た目（プロペラの回転アニメーション）
- チャンク単位のメッシュ化 + VBO キャッシュによる描画最適化
- 物理のワーカースレッド分離（船単位の並列ソルブ）
- 船上ブロックの設置・破壊（構造の動的更新）
- 船 vs エンティティの双方向（重い船に乗ったプレイヤーが船を押す）
